# Security Misconfiguration – Extra Language

## Methodology

1. **Language switching analysis**  
   I changed the application language using the user interface and observed the network requests generated by the browser.

2. **Request inspection**  
   I noticed that changing the language triggered a request to a JSON file located in an internationalization directory, following a predictable naming pattern.

3. **Localization mechanism understanding**  
   The application loads language files directly from the assets directory based on a locale identifier provided by the client.

4. **External resource research**  
   I searched for available translations of the application on the public localization platform used by the project.

5. **Hidden language discovery**  
   I identified an unusual language entry labeled as Klingon, which is not normally exposed through the application interface.

6. **Locale identifier identification**  
   From the localization platform, I retrieved the corresponding locale identifier used for the Klingon translation.

7. **Direct resource access**  
   I manually replaced the locale identifier in the language file request with the one associated with the hidden language.

8. **Language activation**  
   The application successfully loaded the Klingon language file.

9. **Validation**  
   The hidden extra language was displayed in the application, validating the challenge.

### Tools used
- Web browser
- Browser developer tools
- Public localization platform

---

## Vulnerabilities

- **Vulnerability name**: Security Misconfiguration / Improper Access Control
- **Affected components**: Internationalization system, static asset access control
- **Severity level**: Medium

---

## Risks

This vulnerability allows access to application features or content that were not intended to be publicly available.  
Potential business impacts include:
- Exposure of hidden or unfinished features
- Information disclosure
- Loss of control over application configuration
- Increased attack surface

---

## Actions

### Mitigation strategies
- Restrict access to non-public localization resources
- Do not rely on obscurity to hide application features

### Remediation fixes
- Implement server-side validation of allowed locale identifiers
- Remove unused or experimental language files from production
- Enforce strict allowlists for accessible translation assets

### Security best practices
- Apply proper access control to all static and dynamic resources
- Regularly audit production assets for unintended exposure
- Follow OWASP recommendations for secure configuration management
- Treat client-controlled parameters as untrusted input
